# 05-tiercraft（筑层）

筑层 — 数仓分层建设台：贴源入仓 → 明细清洗标准化 → 汇总落表 → 层间行数/键对账。

**不是** 多源 Feed 归并，**不是** 作业依赖编排，**不是** CDC 变更流按序落库，**不是** 质检隔离签发。
**也不是** 报表看板 / CRUD 后台 / 电商订单前台 / OA 工单。

## 启动

```bash
docker compose up --build
```

本地开发：

```bash
# 后端
cd backend
pip install -r requirements.txt
set DATA_DIR=..\data
uvicorn app.main:app --reload --port 10500

# 前端
cd frontend
npm install
npm run dev
```

| 入口 | 地址 |
| --- | --- |
| 前端 | http://localhost:5500 |
| 接口 | http://localhost:10500 |

## 主链

登记主题域 → 按主题域的装载模式装载贴源夹具 → 明细层清洗标准化 → 汇总层聚合 → 层间对账报告与各层列表数字同源

## 贴源装载模式

每个主题域持久化一个装载模式（增量 / 全量，互斥），在「主题域」「贴源层」「分层任务」页配置与执行：

- **增量**：只追加贴源中尚不存在的业务日整日切片；已存在的业务日整日跳过并写入装载报告的跳过清单，不覆盖、不删除已有行（行 id 与原始内容原样保留）。下游明细/汇总保留原地，标记为「待重跑」；若全部业务日都被跳过、贴源未变化，则下游状态保持原样。
- **全量**：清空该主题域贴源后按夹具重载，同时清空明细与汇总，并把主题域置为「待重跑」，避免旧明细/旧汇总被展示为已对齐。此后即便重新生成对账报告，空下游也不会被翻回「已对齐」，只有重跑下游任务后才恢复对齐。

每次装载都在「分层任务」留下任务记录：模式、写入日列表、跳过日列表、写入行数、失败原因，刷新后仍在；贴源层另有按业务日计数可供核对。装载失败时原数据不受影响，失败原因单独记录。

## 装载裁决证明

每次贴源装载都会落一条**装载裁决证明**（新实体 `load_verdicts`，与装载任务 1:1，只追加、不可变），挂在任务 id 上，字段包括：

- 装载模式（增量 / 全量）
- 写入业务日列表、跳过业务日列表（与任务不可变快照列同源）
- 下游是否待重跑（以主题域持久化的下游状态为准，刷新后仍可观察）
- 每个写入/跳过业务日的贴源行数，与贴源按业务日计数同表同源派生

只读查询接口：

| 接口 | 说明 |
| --- | --- |
| `GET /api/load-verdicts/by-job/{job_id}` | 按任务 id 查询单条装载裁决证明，不存在返回 404 |
| `GET /api/load-verdicts?domain_id=` | 查询全部（或按主题域过滤）装载裁决证明 |

「主题域」「贴源层」「分层任务」界面均展示该证明字段；`GET /api/jobs` 的任务视图也内嵌 `load_verdict`。
